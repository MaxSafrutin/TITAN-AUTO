# Локальная подготовка и публикация

По указанию владельца от 25.10.2026:

1. Перед следующими изменениями создать локальную резервную копию текущего проекта вне каталога репозитория.
2. Подготовить и проверить изменения локально; показать владельцу конкретный результат.
3. Загружать на GitHub только после подтверждения изменений и прямой команды владельца на публикацию. Прежняя команда публиковать автоматически больше не применяется.
4. После публикации проверить GitHub Pages и получить подтверждение владельца, что новая версия работает.
5. По уточнению владельца предыдущую резервную копию сохранить для отдельного сравнения. После проверки опубликованной версии создать новую локальную резервную копию, не удаляя старую.

Визитки менеджеров и их URL сохраняются. Превью мессенджеров продолжают использовать текущие изображения Open Graph; изменение фотографии на странице не меняет их автоматически.

## Текущая архитектура

- `assets/audience.js` — два сценария лендинга и исключительное раскрытие разделов.
- `assets/audience.css` — компактная адаптивная разметка лендинга.
- `assets/site-common.js` — общий выбор менеджера, маршруты и мобильное меню.
- `assets/site-common.css` — общие диалоги, шапка и подвал.
- `assets/landing-base.css` — исходные фирменные стили лендинга.
- `managers/assets/cards.css`, `cards.js` — персональные визитки.

Роль посетителя намеренно не сохраняется между открытиями лендинга.
